# BEST-FIT エリア記事の最適解分析：上位表示 × UI（2026-07-07 Fable5）

## 1. 客観比較（実物スクショで確認）

### personal-gym-biyori（参照・良UI）が優れている点
- **構造化された比較体験**: 「選びのポイント3枚」→「料金相場テーブル」→「おすすめ5選（統一フォーマットのジムカード）」→「FAQ」→「関連エリア」と、上から順に読めば判断できる導線。
- **ジムカードが毎回同じ型**: 月額料金／タイプ／営業時間／特徴4点／アクセス／おすすめポイント／Googleクチコミリンク／CTA が全ジム同一構造。**スキャンできる**。
- **料金相場テーブルを上部に**: 「千葉のパーソナルジム料金相場」で検索意図（料金）に即応。
- **Googleクチコミへの外部リンク**（E-E-A-Tの実在シグナル）。

### BEST-FIT現行エリア記事（移植HTML）の弱点
- **冒頭が定型文の壁**: 「自分に合ったパーソナルジムを見つけるのは簡単ではありません…」が90記事でほぼ共通＝**Information Gainが低い**（Googleが「独自価値が薄い」と判断→pos15の主因）。
- **ジム紹介が自由文＝非構造**: 各ジムが長文プロース＋埋め込みバナー画像で、料金・アクセス・特徴が定位置にない。Googleがエンティティ（どのジムが・いくらで）を抽出しづらく、ユーザーもスキャンできない。
- **料金比較テーブルが冒頭にない**（＝料金意図に即応できない）。
- **FAQ構造化データがない**（biyoriはFAQPageあり＝リッチリザルト適格）。
- **自社ジム詳細ページ（/gyms/）への内部リンクがない**：アフィリ外部リンクはあるが、1,318枚ある自社詳細ページへ繋いでおらず、エリアのトピッククラスタを作れていない（最大の機会損失）。

## 2. なぜ現行エリア記事はpos15なのか（SEO診断）
1. 定型的な導入文と自由文構成＝低Information Gain
2. 構造化テーブル・FAQ schema不在＝リッチリザルト非適格
3. 自社詳細ページへの内部リンク不足＝クラスタ弱い
4. ページ間で本文が似通う（テンプレ文）＝カニバリ・薄さ

## 3. 最適解：エリア記事を「自社データ駆動のbiyori型」に再構築
BEST-FITには**biyoriが持たない決定的資産＝1,318枚の構造化ジムデータ（住所・料金プラン・特徴・アフィリリンク）**がある。これを使い、移植の自由文ではなく**データ駆動の構造化ページ**に作り替えるのが、上位表示とUIを同時に取る解。

### 推奨ページ構造（エリア記事の新テンプレ）
1. **ヒーロー（パンくず＋H1）**＝現行踏襲（施主指示のトーン）
2. **地域特化のリード文**（駅・路線・エリア特性を固有情報で。定型文を廃し記事ごとにユニーク化）
3. **料金相場テーブル**（当エリアの実データ由来の目安）
4. **エリアのジム比較テーブル**（ジム×最安料金×アクセス×主要こだわり）＝**自社store dataから生成**。ここがCTR・滞在・スニペットの核
5. **おすすめジムカード（biyori型・統一フォーマット）**＝store dataから生成。各カードは
   - 料金（最安プラン・月額/総額ラベル付き）／アクセス（駅徒歩）／特徴アイコン／
   - **「詳細を見る」＝自社 /gyms/ 詳細への内部リンク**（クラスタ）
   - **「公式サイト」＝そのジムのアフィリリンク**（store.affiliateLinkをそのまま＝1文字も変えない）
6. **こだわり条件で絞り込む**（当エリア×条件の一覧ページへのチップ＝エリア×条件クラスタへ送客）
7. **FAQ（FAQPage schema付き）**
8. **同じエリアの特集記事**（W4で実装済みの地域クラスタ）

### アフィリ保全の担保
各ジムカードのCTAは、そのジムのstore.affiliateLink（＝現行ジム詳細と同一・移行時に照合済み）をそのまま使う。**新規リンクの生成・改変は一切しない**。アフィリを触らずにレイアウトだけbiyori型にできる。

## 4. 上位表示への効果（なぜ効くか）
- 構造化テーブル＋FAQ schema → リッチリザルト適格・スニペット獲得
- 自社詳細への内部リンク → エリアクラスタが強化され評価が集約
- 定型文廃止・地域固有情報 → Information Gain向上
- biyori型の統一カード → 滞在・回遊・CTR改善（UX＝ランキング要因）

## 5. 論点（施主判断が必要）
- **移植した自由文本文を、データ駆動の構造化本文に置き換える**ことになる（現行との“本文パリティ”は崩れるが、施主の狙いは「上位表示＋UI最適」なので、パリティより価値を優先すべき局面）。
- **URLは不変**（/articles/city/yokohama等そのまま）・**アフィリリンクも不変**（store由来）。変わるのは本文の中身と見た目のみ。
- 段階案: まずimp上位のエリア記事（柏・新宿・つくば等）で新テンプレを試験公開→効果を7/14計測で確認→全90記事へ展開。

## 結論（推奨）
エリア記事は**「自社ジムデータ駆動 × biyori型の構造化UI × 自社詳細への内部リンク × FAQ/テーブルschema」**に再構築するのが、上位表示とUIを両立する最適解。URL・アフィリは不変のまま、本文を移植プロースからデータ駆動構造に置換する。まず上位数記事で試験→計測→全展開。
